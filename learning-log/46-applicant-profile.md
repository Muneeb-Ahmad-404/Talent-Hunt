The applicants table uses a UNIQUE constraint on user_id rather than making user_id the primary key. Explain why. What would be different if user_id were the primary key of applicants? Consider foreign key references from other tables (resumes, applications, shortlist_items).

The `applicants` table uses a separate `id` as its primary key while keeping `user_id` as a UNIQUE foreign key to maintain consistency with the rest of the schema, where every table uses `id` as the surrogate primary key for internal references. If `user_id` were the primary key, all foreign key references from tables like `applications` and `shortlist_items` would need to point to `user_id` instead of `applicants.id`, coupling the applicant identity directly to the user identity and making the schema less flexible if the design ever needed to support multiple applicant profiles per user. The current approach keeps foreign key relationships clean and consistent while still enforcing the one-to-one mapping between a user and their applicant profile through the UNIQUE constraint on `user_id`.

A recruiter hits GET /api/applicants/profile and receives a 403. A well-meaning developer suggests removing the requireRole guard and instead returning only the requesting user's own profile. Why is the role guard still necessary even if the query is always scoped to req.user.userId?

Even though the query is always scoped to the authenticated user's ID, the `requireRole('applicant')` guard is still necessary to enforce the API contract and prevent non-applicant users—such as recruiters or admins—from accessing an endpoint that is semantically meant only for applicants, as without it they would either receive an empty response or a confusing 404 instead of a clear 403 Forbidden. The role guard also provides early rejection before any database query runs, communicates the endpoint's intended use clearly to other developers, and prevents accidental misuse if the query logic ever changes, ensuring that the "applicant profile" endpoint is only accessible by users with the applicant role.
