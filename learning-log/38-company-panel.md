The middleware checks for the presence of the access_token cookie but does not verify the JWT signature. A developer proposes verifying the signature in middleware using the jose library (which runs in the Edge runtime). What are the advantages of signature verification in middleware — and what is the risk of relying on the backend to catch tampered tokens on every request instead?

Verifying the JWT signature in middleware using jose allows you to reject tampered or expired tokens at the edge before they ever hit your backend, reducing unnecessary load and improving response times for invalid requests. It also enables you to short-circuit authentication failures early in the request chain, potentially returning 401 responses without invoking application logic. However, the risk of relying solely on the backend is minimal from a security perspective—the backend must verify the signature anyway before processing any authenticated request—but it means invalid tokens still consume backend resources and may expose more surface area if any route accidentally bypasses the verification logic. The trade-off is between edge performance (early rejection) and maintaining centralized, simpler auth logic (backend-only).

The proxy routes add a layer of indirection between the browser and the backend. A developer proposes eliminating the proxies and having client components call the backend directly, storing the access token in localStorage instead of httpOnly cookies. List the security trade-offs of each approach, and state which you would recommend for a job portal that handles applicant data.

Proxy routes with httpOnly cookies store the access token in a secure, JavaScript-inaccessible cookie, making it immune to XSS attacks—critical for a job portal handling sensitive applicant data like resumes and contact information. The proxy layer adds a small latency overhead but keeps the token out of the client's reach, preventing theft via injected scripts. In contrast, storing the token in localStorage exposes it to any XSS vulnerability, allowing attackers to steal it and impersonate users. While eliminating the proxy reduces complexity and latency, the security risk is unacceptable for a system with personal data. I recommend the proxy + httpOnly cookie approach for its superior protection against XSS, which outweighs the minor performance cost.
