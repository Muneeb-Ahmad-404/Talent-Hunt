Consider a scenario where we called getOpenJobs and right after that one of the jobs was closed. Now we have a reference to it and we submit the application for that closed job as well. The open job ids we had were stale. Because of this the application now references a job that is closed so simply put the application is orphaned. The recruiter might get confused for how that application appeared and try to reject it.

Connection pool exhaustion is silent until it is catastrophic. A junior developer asks: "Why not just set the pool max to 1000 connections?" Explain the operating system, PostgreSQL server, and application-level constraints that make a very large pool harmful. What is the typical recommended pool size for a Node.js API server, and how do you calculate the right number for a given workload?

Each pool has limited ram, and overall cpu resources. Along with that nodejs and Psql cant really manage that big of a pool efficiently. If we try to max the pool with 1000 connections, we can experience indefinite wait for our requests, or we could damage our database. The ideal recomended pool size for nodejs is 20-50. And we can calculate based on the given workload too as: size = avg query time / (1 - idle connection ratio)
